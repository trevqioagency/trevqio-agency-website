1. Overview

This site is a set of static HTML files hosted free on GitHub Pages (no server of your own). All the "backend" work — logins, database, file storage, and secure operations — is handled by Supabase, a free-tier backend service. Payments run through Paystack. Visitor tracking runs through Google Analytics. Email notifications (when working) run through Make.com.

Since GitHub Pages can't run code securely on its own, anything sensitive (deleting an account, verifying a payment, inviting a team admin) is handled by small pieces of server-side code called Edge Functions, hosted by Supabase.

Every table uses Row Level Security (RLS) — Postgres rules baked into the database itself that decide who can see or change what. This is why a client can only ever see their own data, and a team admin only sees clients assigned to them, no matter what the website's front-end code does.

7. Troubleshooting cheat sheet

"Site can't be reached" after clicking an email link

Supabase's Authentication → URL Configuration → Site URL is probably still set to the default localhost:3000. It needs to be your real login page URL. This has bitten us twice already.

"Failed to send a request to the Edge Function"

Almost always means the function name in the code doesn't match its real deployed name. Check the URL shown on the function's page in Supabase.

"Edge Function returned a non-2xx status code" with no useful detail

Check that function's Logs tab in Supabase right after reproducing the error — the real reason shows up there.

Data seems to be missing from admin.html but should be there

Run a plain select * from tablename; in the SQL Editor — this bypasses all security rules, so if it's genuinely empty there, the problem is upstream (an insert failed) rather than a permissions issue.

Admin and client accounts "glitch" into each other while testing

Normal — a browser only holds one login per site. Use an incognito window for one of the two, or sign out between switching.

Nothing happens when clicking a button that should show a confirmation popup

Check if a "prevent this page from creating additional dialogs" option ever got checked during testing — it silently blocks all future popups on that tab with zero error. Close the tab fully and reopen.

The whole Supabase project pauses automatically after 7 days with zero activity on the free tier — this also pauses the scheduled weekly backup. A quick visit to any part of the site keeps it awake.
Supabase Storage caps individual files at 50MB on the free tier — large videos will fail to upload.
